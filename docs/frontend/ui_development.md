# ドキュメントのスコープ
本ドキュメントは以下をスコープとする。

- UI開発における基本的な設計思想
- UI開発におけるコンポーネント粒度と再利用方針
- UI開発におけるスタイルの適用方針
- UI開発におけるAIの活用方法

# 基本的な設計思想
このアプリケーションのUI開発においては、本格的なフロントエンド開発者でなくても保守性・可読性の高いコードを書けるような設計を行いつつも、ユーザーにとって使いやすいUI・UXを提供することを目指す。

そのため、以下のようなコードは避けるべきである。
- UI・UXを重視するあまり、煩雑なCSSによってチューニングしすぎること
- コードを簡素にすることを重視した結果、デザイン性に乏しかったり使い方が直感的でないUIを提供してしまうこと

# コンポーネント粒度と再利用方針
このアプリケーションにおけるUI開発では、コード規模の肥大化を防ぎUIの統一感を保つ目的で、UI中の再利用可能な部品を極力コンポーネントとして切り出し再利用する。

コンポーネントの粒度は以下の方針で決定する
- 同じような見た目・機能を持つUI部品は、コンポーネントとして切り出すことを第一に考える
- 複数箇所から呼び出されるコンポーネントにおいて、汎用性を保つためにpropsの数が増えたり条件によって挙動を変える部分が増えてきた場合には、以下の対応などによってコンポーネントの粒度を見直す
  - より粒度の細かいコンポーネントに分割し呼び出し元や薄いコンポーネントで必要に応じて組み合わせる
  - アドホックに増やしすぎたpropsを整理しより本質的なpropsに置き換える

# スタイルの適用方針
このアプリケーションにおけるUI開発では、CSSといったスタイルの適用において、保守性を高め統一勘を保つ目的で、生のCSSを直接書いたりUIライブラリのカスタムプロパティをチューニングすることを避け、デザイントークンやUIライブラリのテーマ機能を活用する。

例えば、
- 直接16進数カラーコードやUIライブラリの色用クラスを使うのではなく、デザイントークンを用いてセマンティックに色を指定する
- 要素毎にUIライブラリのカスタムプロパティを直接記載するのではなく、コンポーネントを活用することで同じ役割の要素を再利用する

# AIの活用方法
このアプリケーションにおけるUI開発では、AIを活用することで、UI開発の効率化や品質向上を図る。
具体的には下記を用いる。

- [Chakra UI MCP](https://chakra-ui.com/docs/get-started/ai/mcp-server): Chakra UIコンポーネントやデザイントークンの情報・バージョン移行に関する情報を取得する
- [Chakra UI Skills](https://chakra-ui.com/docs/get-started/ai/skills): Chakra UIによるUIコンポーネントやテーマの生成やリファクタリングを行う際に利用する

なお、この記載はあくまでもUI開発において特に活用することのできる例であり、これ以外を利用することを妨げるものではない。
