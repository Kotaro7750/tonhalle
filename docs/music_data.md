# ドキュメントのスコープ
本ドキュメントは以下をスコープとする。

- 対応する音源データフォーマット
- メタデータの取得元
- 音源データの取り込みと検証

# 対応する音源データフォーマット
対応する音源データのフォーマットとしては以下とする。

- WAV
- MP3
- AAC
- FLAC
- OGG

なお、これ以外のフォーマットの音源ファイルであっても明確に拒否するわけではなく、外部ライブラリによるサポートなどで再生できる可能性があるがあくまでもベストエフォートである。

# メタデータの取得元
[domain.md](./domain.md)に記載しているようなメタデータについては、音源データに付与されているもののみを取得元とする。

# 取り込みと検証
## 共通の検証
インポートとメタデータインデックスの構築では、Release単位で全ての音源に対して[domain.md](./domain.md)に定義する共通のドメインモデル制約を検証する。
Releaseに所属する全ての音源から取得したRelease用メタデータは、全て一致しなければならない。

一つでも無効な音源があった場合には、そのRelease全体を処理対象から除外する。

## インポート
インポートは、インポート元ストレージから複数のReleaseを読み込み、音源データストレージへRelease単位で保存する。
この際、メタデータインデックスを更新しない。
Releaseと音源の対応づけはインポート元ストレージの具体実装が担い、識別子の生成に用いるメタデータは音源データのみから取得する。

Releaseの識別子は配下の音源から取得したメタデータから導出し、AudioFileの識別子は保存時に発行する。

検証に失敗した場合や同じRelease内に同じTrackIdの音源が複数ある場合は、そのRelease全体をエラーとして保存しない。
また、保存先に同じReleaseIdがすでに存在する場合は、既存のReleaseを上書きせず、そのReleaseのインポートをスキップする。
このような場合でも、他のReleaseの処理は継続する。

## メタデータインデックスの構築
各音源のRelease用メタデータから導出したReleaseIdは、音源データストレージから取得した所属Releaseの識別子と一致しなければならない。

同じRelease内で同じTrackIdのオリジナル音源が複数見つかった場合は、ストレージの列挙順で最初のものを採用する。
後続の音源は警告を出してインデックス登録から除外し、元の音源ファイルは保持する。

異なるRelease間に同じTrackIdが存在する場合は、リリース間の整合性検証でエラーとする。
