# 本ドキュメントのスコープ
本ドキュメントは以下をスコープとする。

- ドキュメントの記載スタイル
- ドキュメントの抽象度

# ドキュメントの記載スタイル
## 見出しによる構造化
ドキュメントはマークダウンを用いて構造化することで認知負荷を軽減する。
その際、以下のルールを遵守すること。

- 子階層の見出しを持つ上位の見出しについては、直下に本文は記載しないこと
  - つまり、本文を持つ階層は見出しのツリーにおいてノードではなくリーフのみに限定する
- ドキュメントのトップレベルには必ず「ドキュメントのスコープ」というトップレベルのセクションを設け、そのドキュメントファイルの記載範囲を明確にすること
- 見出し直後の別の見出しや本文は行を空けることなく記載すること

## 本文の記載スタイル
本文は以下のルールに従って記載すること。

- 文章は平易な日本語で記載すること
- 同じ段落中の文は1行につき1文とし必ず毎文改行すること
- 英単語やインラインコードブロックであっても、前後に半角スペースを入れないこと
- 順序を持たない箇条書きは`-`を用い、順序をもつ箇条書きは`1.`を用いること
- 箇条書きの項目は基本的に1行とし、その場合には末尾に句点を付さないこと
  - 内容上2文以上の方が自然な場合には無理に改行したり1文にまとめず複数文とし、末尾の句点をつける

# ドキュメントの抽象度
ドキュメントの抽象度はドキュメントの種類に応じて適切に設定する。
ただし、同じドキュメントファイル中においては抽象度・粒度は揃えること。

全体として、ドキュメントの抽象度は高くすることを意図している。
これは、ドキュメントにおいて個別具体の事象を網羅的に記載することは、労力がかかり反映漏れが生じやすい上にコードの内容との重複が発生するためである。

ただしこのことは、ドキュメントを曖昧なものにすることとは異なり、ドキュメントをコードの劣化コピーとしないことを意味する。
例えばドメイン上重要なルールの定義の説明などについては、誤解のないような説明を行う。
