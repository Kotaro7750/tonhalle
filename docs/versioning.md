# ドキュメントのスコープ
本ドキュメントは以下をスコープとする。

* 本リポジトリ中の成果物のバージョニング規約
* Gitリポジトリ上の表現

# バージョニング規約
## バージョンニングの概要
本リポジトリでは、リポジトリ全体として画一的なバージョニングを行うのではなく、成果物毎にバージョニングを行う。

また、成果物の種別に応じて異なるバージョニング規約を適用することを前提とする。

## API仕様
本リポジトリ中のアプリケーションによる公開APIの仕様は、[SemVer 2.0.0](https://semver.org/)に従ってバージョニングを行う。
なお、SemVerの仕様上、Major/Minor/Patchの後ろに文字列を付与することができるが、この種別ではMajor/Minor/Patchの3つの数字のみでバージョニングを行う。

## 他のプログラムから使用されるアプリケーション
バックエンドAPIサーバーなど、他のプログラムから使用されるアプリケーションに関しては、[SemVer 2.0.0](https://semver.org/)に従ってバージョニングを行う。
なお、SemVerの仕様上、Major/Minor/Patchの後ろに文字列を付与することができるが、この種別ではMajor/Minor/Patchの3つの数字のみでバージョニングを行う。

SemVerの仕様においては、「公開API」に対する変更範囲を元にバージョニングを行うが、この種別における「公開API」とは、

* APIサーバーが対応するAPI仕様のバージョン
* データベースのスキーマ
* 設定ファイルのスキーマ
* 環境変数・起動時引数の仕様

など、他のプログラムからの利用に影響を与える仕様全体を指すものとする。

## 他のプログラムからの使用されないアプリケーション
フロントエンドSPAなど、他のプログラムからの使用を想定しなくて良いアプリケーションに関しては、[SemVer 2.0.0](https://semver.org/)に従ってバージョニングを行う。
なお、SemVerの仕様上、Major/Minor/Patchの後ろに文字列を付与することができるが、この種別ではMajor/Minor/Patchの3つの数字のみでバージョニングを行う。

SemVerの仕様においては、「公開API」に対する変更範囲を元にバージョニングを行うが、この種別においては他のプログラムからの使用を想定しないため、実質的に「公開API」は存在しないとしてよい。

そのため、本来であればSemVerを適用する必要はないが、npmなどSemVerを前提とするツールは多いため形式としてSemVerを適用することとする。
この際、SemVerにおけるMajor/Minor/Patchは以下のように読み替える。

* Major: 機能面で大規模な変更を伴うバージョン
* Minor: 単純な機能追加など機能面で小規模な変更を伴うバージョン
* Patch: バグ修正やUI調整など機能面での変更を伴わないバージョン

# Gitリポジトリ上の表現
このドキュメントで定義したバージョンはGitリポジトリ上ではタグとして表現する。

また、タグの形式は以下のようにする。 

```
{成果物の識別名}-v{バージョン}
```
